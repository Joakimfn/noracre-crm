# Norwegian and English

The CRM interface and public website support Norwegian Bokmål (`nb`) and English (`en`). Norwegian is the CRM default. The recruiter presentation at `/portfolio` starts in English and includes a separate, fictional-data CRM demo.

## Language selection

- CRM: **My settings → Language**. The preference is remembered in the current browser with the `noracre-language` cookie. Separate subdomains have their own host-only cookies.
- Public website: Norwegian/English links with flags and language names in the header. `?lang=nb` or `?lang=en` takes precedence over the saved preference. Internal links preserve an explicit English selection.
- The root layout resolves the cookie on the server and passes the same locale to HTML and React. There is no process-wide mutable locale and no automatic browser-language detection.
- Language selection is a device preference. It does not change the user profile DTO, trigger profile autosave or need a database migration.

## Translation APIs

- `createI18n(locale)`, `useI18n()` and the typed `messages/nb.ts` / `messages/en.ts` catalogues cover navigation, common messages, plurals, dates and numbers. Both catalogues have matching keys and placeholders.
- `UiText` and `useUiTranslation().ui()` translate developer-authored interface copy using `ui-en.json`. Numeric placeholders such as `{0}` interpolate values once. React escapes rendered output.
- `localizePublicHtml()` translates the website's static text and selected accessible attributes, using `site-en.json` and the shared form catalogue. URL identifiers, input values and enquiry payloads remain unchanged. JSON for client messages is escaped before insertion into HTML.
- Unknown strings are kept as received. New backend/provider error messages should be added to the UI dictionary when appropriate. Never pass customer names, notes, subjects or other user-authored content through the UI translator.

## Stable business data

Database role/status/activity values stay Norwegian. Translate their display labels, never their identifiers. For example, an English **Meeting** button still creates an activity with `kind: 'Møte'`, and a **User** label still corresponds to `role: 'Bruker'`. Authorization checks and select values use the original identifiers.

Language does not convert currency or change billing rules. Prices remain NOK and reporting instants use Europe/Oslo. Calendar dates retain their day; date pickers accept day.month.year on both interfaces. Customer-entered content, historical records, offer/email templates, exported column names, business-register industry names and the CRM's existing legal agreements retain their original language. The public website privacy notice has an English translation.

## Portfolio and demo

`app/portfolio` is an unauthenticated presentation of the project and its sales rationale. Opening the demo supplies `createDemoRuntime().request` through `CrmApiProvider`; the real tenant API is not used. Each demo has its own in-memory data. Email sending, publishing, account connections and external lookups remain blocked by the existing demo runtime. The application repository remains private.

## Verification

Run the focused language and demo tests with:

```sh
node --test tests/language-preference.test.mjs tests/bilingual-portfolio.test.mjs tests/i18n.test.mjs tests/demo-crm.test.mjs tests/public-website.test.mjs tests/module-showcase.test.mjs
```

Run the normal install/build and remaining regression checks using the repository's locked dependencies before deployment. Language tests cover request isolation, initial server language, persistence, escaping, form identifiers, canonical activity identifiers, unchanged prices, administrator controls and demo isolation. No customer-data migration is required for this feature.
